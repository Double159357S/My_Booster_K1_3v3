# 守门员清球与前锋射门

针对实测的“守门员接近球慢”和“前锋碰到球但踢偏”，调整如下：

- 守门员在己方禁区加 0.3 米余量内、球距不超过 2.2 米时，可以申请共享控球权。获得授权后先普通追近；1.2 米内调整身体和清球路线，再启动视觉踢球。未获授权时继续防守。
- 禁区内清球保持守门员角色；球离开清球区域后，才沿用原来的前锋接替守门机制。
- 前锋先追近到 1.4 米内。球偏角不超过 0.35 弧度，身体和接近路线的方向误差不超过 0.25 弧度；不再根据远处球门的开口把启动门槛收紧到几度。
- 需要调整时，平移和转向指令补到步态可响应的最低幅度 0.3，再按行为树速度上限和队友距离限制。角度误差在 0.02 弧度内停止绕球，距离误差在 0.04 米内停止进退；不再一直横移，也不会靠极小的指令等待对准。
- 启动前减速 160 毫秒，结束时允许 0.05 弧度的姿态变化，明显偏转仍取消启动。最近真实球默认保持 650 毫秒，漏检一两帧时按当前位姿投影后继续供给踢球目标；超过该时间后，0.8 米内的旧记忆或预测不能继续踢球。
- 启动、续踢和 `/kick_ball` 发布共用球源选择。普通趟踢沿用自己的方向和避障检查，`safe_shoot` 决策也有对应执行节点。

主要代码在 `src/brain.cpp`、`src/brain_tree.cpp`、`include/utils/kick_strategy.h` 和前锋、守门员行为树中；参数位于 `config/config.yaml` 的 `strategy` 部分。`setup/config.yaml.example` 同步更新。控球权交接协议和队友避碰仍沿用协作版本。

## 编译与验证

使用现有同步脚本，把代码、策略参数和行为树同步到需要更新的机器人，再编译并重启 Demo。三台使用一致的策略参数，每台保留自己的球员号、角色和相机标定。

```bash
./scripts/build_brain.sh
colcon test --packages-select brain --ctest-args -R 'test_(team_cooperation|kick_geometry|kick_strategy|kick_behavior_tree)$' --output-on-failure
colcon test-result --verbose
```

`test_kick_strategy` 覆盖清球区域、授权后接近和调整、踢球朝向、步态忽略小指令时的调整收敛、漏检宽限期及过期停止。`test_kick_behavior_tree` 检查各前锋决策和守门员状态能进入对应动作，包括曾没有执行节点的 `safe_shoot`。这些测试不能代替实机踢球测试。

## 场上复测

1. 守门员：分别把球放在正前方 0.8、1.5、2.0 米，以及禁区内偏左、偏右的位置，观察是否主动接近、对准、清球；球移到禁区外时观察是否返回防守。日志中可看 `[Goalie]` 的状态变化。
2. 前锋：在相同球位、身体初始朝向和目标位置下，旧版和新版各踢 10 次，分别记录进球次数、左右偏差和准备时间。再测试身体偏转约 30° 时是否先对准后出脚。
3. 协作：门前清球时确认前锋让位；清球后确认仍只有一个主攻，另一个接应。

若球到脚边后停住，查看 `brain.log` 中的 `[Striker]`、`[Goalie]` 和 `[RLVisionKick]`：`lead=0` 表示没有控球授权，`ball_age_ms` 表示上次真实球检测的年龄，`approach_error` / `body_error` 表示等待校正的角度，`teammate_distance` 可判断是否在队友制动区。

本地回归通过后，清球速度和射门准确率是否提升仍以实测为准；若完成对准后仍固定向同一侧偏，需要继续检查该机器人的定位朝向和相机标定。
