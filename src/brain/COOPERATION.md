# 3v3 前锋协作

两个前锋同时靠近球时，只有获得共享控球权的机器人追球、调整和踢球；另一台在球的侧后方接应。靠近球不会绕过控球权检查。

## 更新要求

队内通信新增控球权、序号和进程标识，使用 `31204` / 160 字节数据包。**三台机器人必须一起更新 brain、配置和行为树，并重新编译、重启 Demo。** 新版本能读取旧包的状态信息，但旧包不能参与新的控球权确认，不支持混用版本比赛。

每台保留自己的 `game.player_id`、`game.player_role`、相机配置和网络地址，不要把同一份机器人配置直接覆盖到三台上。三台的 `game.team_id`、`game.number_of_players: 3`、协作参数应一致，并开启队内通信。

在已加载 ROS 和工程环境的机器人终端，从 Demo 根目录编译：

```bash
./scripts/build_brain.sh
colcon test --packages-select brain --ctest-args -R 'test_(team_cooperation|kick_geometry|kick_strategy|kick_behavior_tree)$' --output-on-failure
colcon test-result --verbose
```

## 默认行为和参数

### Ready 固定站位

Ready 使用裁判机的守门员编号（未知时按 1 号）排除守门员，再按 `player_id` 从小到大给前锋分配固定位置。同一轮 Ready 内锁定分工，不根据球的位置、到球成本或队友在线数换位置；旧的守门交接指令不影响本轮站位。

9×6 米场地、1 号守门、2/3 号前锋时，默认站位如下。坐标以场地中心为原点，`+x` 是进攻方向，`-y` 是进攻方向右侧。

| 前锋 | 我方开球 Ready | 对方开球 Ready |
| --- | --- | --- |
| 小编号（2 号） | `(-1.15, 0)`，己方中圈附近 | `(-1.60, 0)`，中圈后方 |
| 大编号（3 号） | `(-2.15, -1.80)`，侧后方接应 | `(-2.60, -1.80)`，侧后方接应 |

两个目标相距约 2.06 米。到位容差缩小到 0.25 米，到位后停止，偏离超过约 0.5 米才重新修正。若移动途中两台靠近，大编号先侧移让出小编号的路线，再继续去自己的位置；使用新鲜队友位姿和原有避碰约束。进入 PLAY 后按原有控球权协作进攻。

手动同步、编译并启动后，先发 Ready，检查两台目标是否不同；再交换两台的初始位置重试，确认目标仍按编号分配、相遇时大编号让行。日志中的 `[Ready] player=... target=(...)` 可以核对实际目标。新增 C++ 站位检查包含不同守门员编号、跨 Ready 重置、站位安全余量及近距离让行；本次未执行 C++ 编译或实机测试。

### 比赛协作参数

| 参数（strategy.cooperation 下） | 默认值 | 含义 |
| --- | --- | --- |
| comm_fresh_ms | 800.0 | 队友消息过期时间，毫秒 |
| owner_lease_ms | 1200.0 | 控球授权期限，毫秒 |
| owner_hold_ms | 1500.0 | 主攻最短保持时间，毫秒 |
| owner_switch_margin | 0.75 | 换主攻所需的到球成本优势 |
| owner_confirm_ms | 500.0 | 成本优势持续确认时间，毫秒 |
| support_back_distance | 1.4 | 接应点在球后方的距离，米 |
| support_side_distance | 1.2 | 接应点的横向距离，米 |
| teammate_stop_distance | 0.8 | 禁止继续靠近队友的距离，米 |
| teammate_slow_distance | 1.3 | 开始限制接近速度的距离，米 |
| teammate_approach_speed | 0.4 | 减速区接近速度上限，米/秒 |

通信正常的、已定位的最小球员号负责发布控球权，其他机器人回传确认。3 人均未受罚时，需要至少 2 台确认；孤立的机器人不会自行抢球。主攻只有进入 AI 足球模式且知道球的位置时才参与候选。正常交接先撤销旧授权，留出退出踢球的时间，再授权下一台；协调机器人更换时默认等待约 1.95 秒。

接应方向在同一控球轮次内保持稳定，优先避开主攻手到球的路线；场地边缘会限制目标点。远距离追球、接应恢复原 Demo 的速度上限 1.6、1.2 米/秒；1 米内追球限速 0.6 米/秒，并开启追球避障。普通速度命令限制朝队友靠近的分量，保留后退和侧移；视觉踢球检查队友是否占用脚边或清球通道。

普通 PLAY 中，挡住主控的非主控先让行，再执行接应或守门；非主控守门员让开后暂时保持，避免马上回到门前挡住清球。直接看见 1.2 米内球的合格候选优先于只靠共享位置的候选；正在执行 SDK 时保持主控。禁区聚集的问题分析、改动和复测见 [BALL_OWNERSHIP.md](BALL_OWNERSHIP.md)。

队友避碰依赖定位和新鲜通信，不能代替视觉避障。实机仍需验证定位误差、通信延迟和制动距离。此改动实现主攻/接应分工，未增加新的传球识别或传球执行策略。

## 球位置共享与己方禁区清球

队友的新鲜直接视觉报告可用于接近、转头找球和申请控球，距离自己不足 1.5 米的球也能共享。旧 `strategy.tm_ball_dist_threshold` 保留兼容读取，不再按此距离丢弃球。选择报告时检查消息年龄、置信度和场地范围，优先采用距离球较近的视觉来源；本机新鲜视觉优先于队友坐标。

守门员在己方清球范围内可用共享球申请控球并接近。前锋也能凭共享球申请主攻，仍由多数确认保证只有一台主控。共享球不会冒充本机检测、刷新真实球检测时间或启动踢球。主控偏角较大时先原地转向，对准后接近；约 0.65 米内停步，在共享球方向附近按中央、左、右、上、下、中央做一轮头部扫描。本机重新看见球后立即交回正常视觉跟踪。

共享搜索使用同一个恢复状态：`CamTrackBall` 只发头部指令，`Chase` 负责身体运动。搜索阶段在每帧控球权仲裁完成后更新；接应、等待对方开球、球出界、手动模式和 SDK 踢球期间不消耗主控扫描预算。小幅坐标抖动、观测来源切换和同目标的新消息不会重置计时。近球距离有 0.12 米滞回，避免阈值附近反复退出扫描。共享报告过期立即停止主动恢复，同时保留已失败目标的锁定。

默认累计近球扫描 2.5 秒仍无法重识别时释放资格，交给其他候选；超时至少覆盖一次完整扫描。近球转向始终无法完成时，累计主控近球尝试达到两倍扫描超时也会释放。非主控、转向或报告中断不刷新已累积的扫描时间。失败后仅球相对本次目标锚点移动超过 0.4 米或本机重新看见球，才恢复同目标的追球资格。

参数在 `strategy.shared_ball_search` 下，实际配置和初始化模板同步提供：

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| stop_distance | 0.65 | 停步重识别距离，米 |
| turn_angle | 0.6 | 远球先原地转向的偏角门槛，弧度 |
| vtheta_limit | 0.8 | 共享球追逐时的转向角速度上限，弧度/秒 |
| scan_delay_ms | 400.0 | 指向目标后的识别等待时间，毫秒 |
| scan_step_ms | 250.0 | 每个扫描点的停留时间，毫秒 |
| scan_yaw / scan_pitch | 0.35 / 0.15 | 相对共享目标的左右/上下扫描幅度，弧度 |
| timeout_ms | 2500.0 | 主控近球扫描失败的累计超时，毫秒 |
| target_move_distance | 0.4 | 相对固定目标锚点重置搜索的移动距离，米 |

共享球扫描的头部命令限制在 yaw ±1.1、pitch 0～1.1 弧度内，并继续经过原有机器人软限位。参数中的非有限值回退到默认值，范围越界值被限制；无需放宽用于通信及球权仲裁的 `comm_fresh_ms`。

每秒输出一行 `[Team]`，包含队友在线数、球来源、`shared_from`、`shared_search`、`search_phase_ms`、控球候选资格、主控号及各队友消息年龄。`shared_search` 为 inactive/support/turn/approach/scan/released，扫描阶段的毫秒数为累计实际扫描时间，其余阶段为本次进入阶段后的时间。3 台均具备上场和定位资格时应看到 `online=2/2`。`age_ms` 持续超过 `comm_fresh_ms` 表示消息过期；年龄新鲜而 `alive=0` 时检查队友定位、受罚和起身状态。`protocol=0` 表示尚未收到当前协议消息，需核对版本。

本队 `team_id: 70` 使用机器人之间的 **UDP 10070**；裁判机状态回包使用的 UDP 3939 是另一条链路。裁判机绿色勾不能证明队友通信正常。三台应使用相同队号、人数和程序版本，不同球员号，并全部启用 `enable_com`。队友收不到消息时检查机器人所在 Wi-Fi 的客户端隔离及 UDP 10070 的网络放行。

查看日志：

```bash
grep '\[Team\]' brain.log | tail -n 10
```

## 回归测试

`test_team_cooperation` 覆盖成本抖动、持续优势交接、踢球期间保持主攻、退出踢球后的交接、协调机器人断联及重启、无多数确认、丢包与乱序、缓存授权过期、四种通信包格式，以及接应路线和多队友速度约束。共享球回归覆盖一台前锋看见球而另外两台看不见、禁区近球、过期及转发报告拒绝、守门员授权与重识别失败后的交接；新增完整扫描、消息抖动、距离滞回、仲裁后授权同步、通信中断及同目标失败锁定。`test_soccer_flow_runtime` 直接执行生产版相机、追球和决策函数，检查转向、接近、停步扫描、头部限位、报告失效和本机视觉接管。`test_kick_geometry` 保留原有踢球几何测试。

守门员清球和前锋射门的更新、参数与复测步骤见 [KICKING.md](KICKING.md)，`test_kick_strategy` 验证清球、对准和球源有效期，`test_kick_behavior_tree` 验证决策的动作入口。
