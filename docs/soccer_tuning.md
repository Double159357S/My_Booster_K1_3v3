# 踢球、守门与双机配合调试

## 本次修改

- 踢球前同时检查身体朝向、机器人到球的方向与期望射门方向。前锋默认误差上限由 1.8 rad 改为 0.2 rad（约 11.5°），守门员解围改为 0.35 rad。启动减速结束后再次检查，避免减速期间球移动造成误踢。
- 真实球观测默认最多保留 250 ms 用于踢球，默认禁止用记忆或预测球替代踢球消息。守门员的有效预测拦截目标保留原有专用路径。追球仍可使用可靠队友球位置；队友提供的球不会伪装成本机实际检测。
- 守门员根据球到达拦截平面的时间计算所需横向速度，并保留比例控制作为下限。预留 0.15 s 响应时间，速度不超过原配置 0.8 m/s。身体朝向球场正方向，避免随侧方球转身而降低横移效果。
- 队友 UDP 默认向每个启用的 IPv4 广播接口发送，避免多网卡环境只向默认路由广播。可指定 `strategy.cooperation.broadcast_address` 限定广播地址。
- 保留原有带租约、多数确认和成本滞回的球权仲裁。允许可靠共享球参与上球选择，去除旧成本排名对已授予球权的重复限制。相同队伍重复 player_id 会报错。

## 部署

在所有参赛机器人上部署同一版本，并停止原程序再编译：

```bash
cd ~/Workspace/robocup_demo
./scripts/stop.sh
./scripts/build.sh
```

仓库示例配置不能直接覆盖每台机器的身份和标定。将新增/修改的策略参数合并进现有 `src/brain/config/config.yaml`；如果 launch 使用 `config_local.yaml`，也要合并进去。保留各机器人相机标定、网络、场地与身份配置。

每台机器人必须设置相同 team_id、不同 player_id，player_id 在 1..num_of_players 范围内，开启 `enable_com`。角色按实际用途选择 striker / goal_keeper。两台机器人测试时 roster 设置为 2，并与 GameController 的队伍和处罚状态一致。双方使用同一可互通局域网，允许 UDP `10000 + team_id`；AP 客户端隔离必须关闭。

如需限定比赛无线网广播，在双方设置实际子网广播地址，例如 `/24` 的 192.168.10.x 网络：

```yaml
strategy:
  cooperation:
    broadcast_address: "192.168.10.255"
```

示例地址仅适用于该子网；根据实际 IP/掩码填写。启动日志显示实际广播目标。网络接口变化后重启 brain。

## 实机检查

在有足够空间、遥控可接管的条件下启动 `./scripts/start.sh`。先检查 `brain.log` 中低频状态：

- `team owner`：双方应显示同一个 owner，只有 owner 对应机器人 `granted=1`。
- `peer age_ms`：连续更新且低于 comm_fresh_ms（默认 800 ms）；`protocol=ownership`、`alive=1`、`ready=1`。legacy/absent 表示未收到新版协议或对方程序版本过旧，不能完成球权确认。
- `shared_ball=1`：收到可靠队友观测。共享球可用于追球，实际踢球需有效本机视觉或守门员专用拦截目标。
- owner=0：检查队友消息、比赛处罚、自动控制状态、定位是否完成和球是否已知。通信不足多数确认时不会允许两个机器人独立抢球。

保持球位置，分别从正前、斜前方向接近，确认先调整再踢球。记录命中率和偏差；若持续向同一侧偏，检查相机外参、球定位、里程计和踢球固件，不能只放宽角度条件。

守门测试逐渐增加来球速度，记录横移是否及时。0.8 m/s 是命令上限，实际速度受固件、步态、地面和侧向加速度限制；只有完成实机测量后才调整 goalie_simple_vy_max 和 robot.vy_limit。

双机测试先令两台机器人均可见球，再遮挡其中一台视线、改变双方到球距离并断开网络。应保持唯一上球者；持续成本改善后交接；通信失联后撤销球权。进入踢球后，不因短时成本变化抢占正在踢球的队友。

## 验证范围

新增回归检查覆盖身体/球方向不一致、角度跨 ±π、紧急横移、速度限幅、无效球输入、双机球权和 UDP 地址/收发。已有丢包、乱序、租约到期、协调者重启及避碰测试保留。

开发机通过独立 C++17 测试和 YAML 解析；尚未在机器人 ROS Humble 环境进行完整构建或实机验证。不能据此宣称射门命中率、实际横移速度或比赛无线网络已经达到目标。
